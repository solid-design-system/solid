# CDN Hosting

Solid Design System does **not** provide a hosted CDN. The recommended installation method is npm — see the [Quickstart](?path=/docs/packages-quickstart--docs).

If you work in an environment without a bundler (e.g. a CMS), the npm packages include pre-built artifacts under `cdn/` that you can serve from **your own CDN**. Each team is responsible for hosting and caching these files.

<sd-notification variant="warning" open>
  There is no Solid-managed CDN endpoint. Any CDN URL you use must point to an infrastructure your team controls.
</sd-notification>

## Available artifacts

After `npm install`, the following files can be copied to your CDN:

| Package                           | Path in package                  | Description                       |
| --------------------------------- | -------------------------------- | --------------------------------- |
| `@solid-design-system/tokens`     | `cdn/themes/<theme>/<theme>.css` | Theme CSS                         |
| `@solid-design-system/styles`     | `cdn/solid-styles.css`           | All styles, pre-bundled           |
| `@solid-design-system/components` | `cdn/solid-components.css`       | Component base CSS                |
| `@solid-design-system/components` | `cdn/solid-components.js`        | ESM — registers all components    |
| `@solid-design-system/components` | `cdn/solid-components.bundle.js` | Bundle — all dependencies inlined |

All three packages also ship a `cdn-versioned/` variant where component tag names include the version number (e.g. `<sd-%DASHED-COMPONENTS-VERSION%-button>`). Use this in microfrontend environments to prevent tag name collisions when multiple versions run on the same page.

## Self-hosted CDN

Replace `https://your-cdn.example.com` with your actual CDN base URL. All three packages must use the same version number.

## cdn/ vs dist/

The `cdn/` files are pre-bundled with all dependencies inlined — they work without a build tool. The `dist/` files are not pre-bundled, so a bundler can deduplicate shared dependencies across your whole app for a smaller total bundle size. Use `dist/` whenever you have build tooling available.

## Prototyping with jsDelivr

For quick prototypes, CodePens, or one-off experiments you can load the packages directly from [jsDelivr](https://www.jsdelivr.com/) — no infrastructure needed. **Do not use this in production.**
