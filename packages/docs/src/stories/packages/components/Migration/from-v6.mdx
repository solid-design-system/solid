## CDN publishing ended, migrate to npm

Starting with this release, Solid Design System no longer publishes new versions to a Solid-managed CDN endpoint.
For updates beyond v6, install and consume the packages via npm.

If you still need CDN delivery in production, host the `cdn/` or `cdn-versioned/` artifacts from npm on infrastructure your team controls.

**Before (v6 CDN loading from the Solid-managed endpoint)**:

```html
<link
  rel="stylesheet"
  href="https://solid-design-system.fe.union-investment.de/components/6.29.0/cdn/solid-components.css"
/>
<link rel="stylesheet" href="https://solid-design-system.fe.union-investment.de/styles/6.29.0/cdn/solid-styles.css" />
<link
  rel="stylesheet"
  href="https://solid-design-system.fe.union-investment.de/tokens/6.29.0/cdn/themes/ui-light/ui-light.css"
/>
<script
  type="module"
  src="https://solid-design-system.fe.union-investment.de/components/6.29.0/cdn/solid-components.bundle.js"
></script>
```

**After (npm usage)**:

```bash
npm install @solid-design-system/components @solid-design-system/styles @solid-design-system/tokens
```

```js
import '@solid-design-system/tokens/dist/themes/ui-light/ui-light.css';
import '@solid-design-system/styles/dist/solid-styles.css';
import '@solid-design-system/components/dist/solid-components.css';
import '@solid-design-system/components/dist/solid-components.js';
```

For self-hosted CDN setups, artifact paths, and jsDelivr-based prototyping (for example CodePen demos and quick experiments), see [General/CDN Hosting](?path=/docs/general-cdn-hosting--docs).

## Component updates

### `sd-teaser` headline slot no longer enforces styles

Previously, `sd-teaser` used `!important` to force `font-size`, `font-weight`, and `margin` on whatever element was placed in `slot="headline"`, preventing any overrides from Light DOM styles.

These `!important` declarations have been removed. The same defaults still apply when no conflicting styles exist, but **any author-level styles targeting the headline element (e.g. global `h3` rules) will now take effect**.

**Who is affected:** Users who have heading styles in their stylesheets and rely on `sd-teaser` suppressing them.

**Before** (global `h3` styles were silently ignored):

```css
h3 {
  font-size: 2rem;
  margin: 1rem 0;
} /* had no effect inside sd-teaser */
```

**After** (global `h3` styles now apply):

```css
h3 {
  font-size: 2rem;
  margin: 1rem 0;
} /* now visible inside sd-teaser */
```

To restore the previous fixed appearance, apply the size explicitly on the slotted element:

```html
<sd-teaser>
  <h3 slot="headline" class="sd-headline sd-headline--size-lg">Headline</h3>
</sd-teaser>
```

### `<sd-input>` and `<sd-textarea>`

The `autocorrect` property is now a `boolean` instead of a `string`. This is required by the updated `HTMLElement.autocorrect` type shipped in TypeScript 5.9, which now matches how browsers implement the native `autocorrect` IDL attribute.

The `autocorrect` HTML attribute is unaffected and still accepts `"on"` and `"off"`, so no markup changes are needed.

```html
<!-- No changes required -->
<sd-input autocorrect="off"></sd-input>
<sd-textarea autocorrect="off"></sd-textarea>
```

Only code that sets the property directly in JavaScript/TypeScript needs to be updated:

**Before:**

```js
input.autocorrect = 'off';
```

**After:**

```js
input.autocorrect = false;
```

### Removed sd-spinner

The `sd-spinner` component has been removed from the library.
Please use `sd-loader` instead.

**Before**:

```html
<sd-spinner></sd-spinner>
```

**After**:

```html
<sd-loader></sd-loader>
```
