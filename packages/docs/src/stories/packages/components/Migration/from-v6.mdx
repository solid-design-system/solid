## `sd-teaser` headline slot no longer enforces styles

Previously, `sd-teaser` used `!important` to force `font-size`, `font-weight`, and `margin` on whatever element was placed in `slot="headline"`, preventing any overrides from Light DOM styles.

These `!important` declarations have been removed. The same defaults still apply when no conflicting styles exist, but **any author-level styles targeting the headline element (e.g. global `h3` rules) will now take effect**.

**Who is affected:** Users who have heading styles in their stylesheets and rely on `sd-teaser` suppressing them.

**Before** (global `h3` styles were silently ignored):

```css
h3 {
  font-size: 2rem;
  margin: 1rem 0;
} /* had no effect inside sd-teaser */
```

**After** (global `h3` styles now apply):

```css
h3 {
  font-size: 2rem;
  margin: 1rem 0;
} /* now visible inside sd-teaser */
```

To restore the previous fixed appearance, apply the size explicitly on the slotted element:

```html
<sd-teaser>
  <h3 slot="headline" class="sd-headline sd-headline--size-lg">Headline</h3>
</sd-teaser>
```

## Component updates

### `<sd-input>` and `<sd-textarea>`

The `autocorrect` property is now a `boolean` instead of a `string`. This is required by the updated `HTMLElement.autocorrect` type shipped in TypeScript 5.9, which now matches how browsers implement the native `autocorrect` IDL attribute.

The `autocorrect` HTML attribute is unaffected and still accepts `"on"` and `"off"`, so no markup changes are needed.

```html
<!-- No changes required -->
<sd-input autocorrect="off"></sd-input>
<sd-textarea autocorrect="off"></sd-textarea>
```

Only code that sets the property directly in JavaScript/TypeScript needs to be updated:

**Before:**

```js
input.autocorrect = 'off';
```

**After:**

```js
input.autocorrect = false;
```

## Removed sd-spinner

The `sd-spinner` component has been removed from the library.
Please use `sd-loader` instead.

**Before**:

```html
<sd-spinner></sd-spinner>
```

**After**:

```html
<sd-loader></sd-loader>
```

## Removed the default margin from inline `sd-notification`

Inline `sd-notification` components no longer include the default `0.5rem` margin. Toast notifications displayed through `.sd-toast-stack` retain their existing spacing. If your inline notifications relied on the previous spacing, add it manually via the `base` CSS part.

**Before**:

```html
<sd-notification open>Notification message</sd-notification>
```

The component applied its own margin.

**After**:

```html
<sd-notification class="my-notification" open>Notification message</sd-notification>

<style>
  .my-notification::part(base) {
    margin: 0.5rem;
  }
</style>
```
