# Migration from v6

The v6 release improves token stability, cleans up unused CSS variables, and introduces several fixes and refinements across different components.

Dear devs, when adding a migration guide, please include:

1. What changed and why
2. Who is affected
3. The required migration steps
4. A “Before” and “After” example, when applicable

Remove all placeholder comments before the release.

## Breaking change #1

### Removed the default margin from inline `sd-notification`

Previously, the `base` part of every `sd-notification` had a default margin of `0.5rem`. This also affected inline notifications and could make them difficult to align with their surrounding layout.

The default margin has been removed from the component's `base` part. Notifications displayed as toasts keep their existing spacing because `.sd-toast-stack` now applies the margin to the `wrapper` part instead and resets the `base` margin to `0`.

You are affected only if your inline notifications rely on the previous default spacing. In that case, add the required spacing explicitly through your layout or the `base` CSS part.

**Before**:

```html
<sd-notification open>Notification message</sd-notification>
```

The notification's `base` part automatically had a margin of `0.5rem`.

**After**:

```html
<sd-notification class="my-notification" open>Notification message</sd-notification>

<style>
  .my-notification::part(base) {
    margin: 0.5rem;
  }
</style>
```

Inline notifications without additional styling now have no margin and align directly with their containing layout.
