# Migration from v6

The v6 release improves token stability, cleans up unused CSS variables, and introduces several fixes and refinements across different components.

<div hidden>
Dear devs, when adding a migration guide, please include:

1. What changed and why
2. Who is affected
3. The required migration steps
4. A “Before” and “After” example, when applicable

Remove all placeholder comments before the release.

## Removed enforced headline styling from `sd-teaser-media`.

Removed this CSS rule that used to force styles into whatever is slotted into slot="headline"

```css
::slotted([slot='headline']) { '@apply font-bold !m-0 !text-lg;'}
```

Result: `sd-teaser` no longer forces font-weight, margin or test size on headline elements. Headline sizing/spacing must now be provided by the user.

**Before**:

```html
<sd-teaser>
  <h3 slot="headline" class="sd-headline">Expert views</h3>
</sd-teaser>
```

**After**:

```html
<sd-teaser>
  <h3 slot="headline" class="sd-headline sd-headline--size-lg">Expert views</h3>
</sd-teaser>
```

## Component updates

### `<sd-input>` and `<sd-textarea>`

The `autocorrect` property is now a `boolean` instead of a `string`. This is required by the updated `HTMLElement.autocorrect` type shipped in TypeScript 5.9, which now matches how browsers implement the native `autocorrect` IDL attribute.

The `autocorrect` HTML attribute is unaffected and still accepts `"on"` and `"off"`, so no markup changes are needed.

```html
<!-- No changes required -->
<sd-input autocorrect="off"></sd-input>
<sd-textarea autocorrect="off"></sd-textarea>
```

Only code that sets the property directly in JavaScript/TypeScript needs to be updated:

**Before:**

```js
input.autocorrect = 'off';
```

**After:**

```js
input.autocorrect = false;
```

## Removed sd-spinner

The `sd-spinner` component has been removed from the library.
Please use `sd-loader` instead.

**Before**:

```html
<sd-spinner></sd-spinner>
```

**After**:

```html
<sd-loader></sd-loader>
```

## Updated the `sd-dialog` footer layout

`sd-dialog` no longer aligns footer actions automatically. Wrap the actions in a full-width element assigned to the
`footer` slot and define their layout on that element.

**Before**:

```html
<sd-dialog headline="Cancel your subscription?">
  <p>Your subscription will be canceled immediately.</p>
  <sd-button slot="footer" variant="secondary">Maybe later</sd-button>
  <sd-button slot="footer" variant="primary">Cancel subscription</sd-button>
</sd-dialog>
```

**After**:

```html
<sd-dialog headline="Cancel your subscription?">
  <p>Your subscription will be canceled immediately.</p>
  <div slot="footer" class="flex flex-col-reverse sm:flex-row justify-end w-full gap-2">
    <sd-button variant="secondary">Maybe later</sd-button>
    <sd-button variant="primary">Cancel subscription</sd-button>
  </div>
</sd-dialog>
```
