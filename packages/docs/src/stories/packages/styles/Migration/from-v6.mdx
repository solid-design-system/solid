# Migration from v6

The v6 release improves token stability, cleans up unused CSS variables, and introduces several fixes and refinements across different components.

## `sd-flag` and `sd-chip` consolidated

`sd-chip` and `sd-flag` were consolidated into a single non-interactive label component, `sd-chip`. The updated component offers multiple color and shade options, fill and outline variants, and rounded or sharp corners. This provides consumers with a consistent way to label UI elements without having to choose between two components with overlapping purposes.

**Who is affected:**

- Anyone using the `sd-flag`.
- Anyone using the default `sd-chip`.
- Anyone using the previous `sd-chip--primary-200 | --primary-300 | --primary-500 | --white` variants.

**Migration steps:**

- Replace every `sd-flag` occurrence with `sd-chip` and add the appropriate `&--color-*`, `&--shade-*` and, if you need the larger flag height, `sd-chip--size-lg`. Add `sd-chip--sharp` to match the original flag's non-rounded corners.
- Replace the old `sd-chip` variants with the new `&--color-*` / `&--shade-*` combination.
- Update any custom overrides that targeted the removed CSS variables to the new names. Check the [tokens migration guide to v6](./?path=/docs/packages-tokens-migration-from-v6--docs).
